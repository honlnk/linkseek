# 云端搜索优先开发计划

> 状态：待确认
> 日期：2026-11-06
> 目标：默认优先使用商业云端搜索，提高召回质量并减少无效重试；仅在云端不可用或未返回结果时，最后使用本地 SearXNG 搜索。
> 范围：统一搜索路径、全部现有搜索入口、空结果诊断、管理后台说明、公开文档与配套使用技能。

## 一、背景与目标

现有默认搜索先执行 SearXNG 降级链，全空后才尝试商业引擎；商业搜索只能通过基础搜索工具的显式云端参数直接调用。实际使用中，云端结果的相关性与来源质量明显更好，逐次手动指定云端路径增加了不必要的操作和等待。

本次将默认路径改为「云端优先、本地最后兜底」。SearXNG 继续运行，不删除，也不改变现有本地降级重试策略。云端未配置、凭证失效、请求失败或返回空结果时，都进入本地搜索，保证原部署和异常情况下仍有搜索能力。

## 二、定稿行为约定

### 2.1 默认路径

1. 按后台已有的商业引擎顺序逐一搜索，任一引擎返回结果后立即返回，不重复调用后续云端引擎。
2. 云端全部返回空结果、不可用或请求失败时，执行现有 SearXNG 降级重试链；任一尝试返回结果后立即返回。
3. 两边都没有结果时，返回包含完整尝试记录的空结果报告。
4. 云端未配置引擎列表、全部停用或凭证均不可用时，不发出云端请求，直接执行本地搜索，行为与未配置商业引擎的部署兼容。
5. 不因云端结果数量少、质量疑似不足或评分低而继续调用本地搜索；以是否返回结果作为唯一切换条件。

### 2.2 参数与显式选择

| 调用方式 | 搜索行为 |
|---|---|
| 不传搜索路径，或选择自动模式 | 云端依次搜索 → 云端未命中 → SearXNG 降级链 |
| 选择云端模式 | 与默认路径相同：云端优先，未命中时由本地最后兜底 |
| 显式指定 SearXNG 引擎参数 | 跳过云端，直接执行本地降级链，保留指定特定本地引擎的能力 |
| 本地、云端均未返回结果 | 返回空结果及诊断，不额外重试同一引擎 |

保持现有两个路径取值的兼容性，不新增第三个枚举值。自动模式与云端模式的区别从「是否先走本地」变为历史兼容别名；显式指定本地引擎是跳过云端的明确信号。其余参数继续传给 SearXNG；商业引擎仅接收查询词和结果数量，这一现有限制保持不变。

### 2.3 统一生效范围

以下入口统一采用新的默认路径，不逐一新增参数：

- 基础联网搜索；
- 搜索并抓取；
- 搜索并由 AI 综合回答；
- 深度研究中的多轮搜索；
- 公开搜索接口，包括 API Key 调用和匿名免费调用。

匿名调用仍执行现有来源白名单、每日配额和突发限流，但会消耗部署者的云端账号额度；这是本次默认策略的一部分。后台和文档必须明确这一点。

### 2.4 诊断与日志

1. 云端尝试记录保持独立类别，并按实际顺序出现在本地尝试之前。
2. 云端未命中而本地命中时记录明确日志，便于观察本地兜底是否真正接管。
3. 云端全部失败且本地也失败时，向调用方抛出本地最终错误，同时保留云端诊断；不以「云端成功」掩盖最终失败。
4. 空结果文案按「云端搜索已尝试 → 本地降级链已尝试」如实展示，不再把云端描述为只在链尾出现的兜底。
5. 日志不得输出查询凭证或完整密钥，沿用现有脱敏与熔断机制。

### 2.5 配置与数据迁移

- 无数据库结构变更，无存量数据迁移。
- 后台商业引擎列表及其顺序、启停状态、凭证全部保留，不自动重排。
- 不新增全局开关：云端列表为空即自然退回本地；停用全部云端引擎可恢复本地优先的实际效果。
- 已保存的云端列表继续生效，升级后默认路径立即改变，无需管理员重新保存。

## 三、新旧机制去向

| 机制 | 去向 |
|---|---|
| 商业引擎管理器与引擎排序 | 保留，改作默认第一顺位搜索 |
| SearXNG 与现有降级链 | 保留，改作最后兜底 |
| 显式云端参数 | 保留，语义调整为云端优先并允许本地兜底 |
| 自动模式 | 保留，默认改为云端优先 |
| 显式本地引擎参数 | 保留并强化为跳过云端的明确选择 |
| 商业引擎「仅作兜底」的后台及文档表述 | 替换为「云端优先，本地兜底」 |
| 未配置云端时的本地搜索能力 | 保留，无感兼容 |

## 四、实施步骤

### 阶段一：统一搜索路径

1. 重构统一搜索入口，将「云端搜索」「本地降级链」编排为可分别测试的两个阶段。
2. 按本计划处理默认、云端、显式本地引擎三类调用。
3. 合并诊断记录和异常处理，确保云端故障不会阻断本地兜底。
4. 更新空结果报告，准确区分云端与本地尝试。
5. 更新单元测试，至少覆盖：
   - 默认云端命中时不调用本地；
   - 云端按既有顺序命中后停止；
   - 云端返回空、未配置、停用、凭证不可用、请求失败时均进入本地；
   - 本地命中后正确返回，诊断顺序完整；
   - 两边都空时返回完整诊断；
   - 两边都失败时抛出最终错误且云端诊断不丢失；
   - 显式指定本地引擎时不调用云端；
   - 云端模式也允许本地最后兜底。

**门禁**：全部测试通过、类型检查干净；计划状态与施工日志同步写盘。

### 阶段二：界面与文档同步

1. 管理后台搜索设置页改为说明云端优先级、本地兜底和匿名调用的云端额度消耗；引擎列表与凭证管理交互不变。
2. 更新项目说明、公开使用文档和现有搜索设计文档，使默认路径、参数含义和部署风险一致。
3. 经用户明确授权后，更新配套使用技能：常规搜索不再要求手动指定云端，失败处理不再重复切到云端；保留改写查询、查看诊断与必要时使用宿主搜索的指引。
4. 不修改历史施工日志，不改动与本需求无关的旧调研文档。

**门禁**：全部测试、类型检查和完整构建通过；文档同步写盘。

### 阶段三：真实环境验收

1. 使用现有真实云端凭证验证普通中文、英文和技术查询，确认默认调用无需手动指定云端即可返回高质量结果。
2. 使用模拟故障验证云端失败后本地接管，避免为制造故障而修改或暴露真实凭证。
3. 验证未配置云端的部署仍可直接本地搜索。
4. 验证基础搜索、搜索并抓取、AI 综合回答、深度研究及公开搜索接口均走统一路径。
5. 验证显式指定本地引擎仍跳过云端。
6. 核对后台文案、空结果诊断和日志，无凭证泄漏。

**门禁**：自动化与构建全绿；真实服务依赖项按实际执行结果列入验收记录。部署与推送不属于本计划，须另行明确执行。

## 六、本期不做

- 不删除 SearXNG 容器、配置或相关代码。
- 不调整现有云端引擎默认排序，不自动把 Exa 或 DeepSeek 提到 Devin 前。
- 不新增商业引擎，不更换供应商，不修改凭证存储方式。
- 不增加结果数量阈值、质量评分、多路结果合并或云端与本地并发竞速。
- 不新增搜索路径设置开关或第三路径枚举。
- 不调整公开接口的每日配额、限流、鉴权与匿名开放策略。
- 不处理此前观察到的用量漏记、startpage 验证码、应用健康检查等独立问题。
- 不在本期自动发布或部署。

## 七、验收标准

| 场景 | 预期结果 | 验证方式 |
|---|---|---|
| 普通搜索且云端正常 | 直接返回云端结果，本地无请求 | 单元测试 + 真实查询日志 |
| 云端返回空 | 自动执行本地搜索 | 单元测试 |
| 云端不可用或异常 | 本地接管，不向调用方误报云端成功 | 单元测试 + 模拟故障 |
| 未配置任何云端引擎 | 直接执行原有本地搜索 | 单元测试 + 无云端配置环境 |
| 显式指定本地引擎 | 跳过云端，尊重指定引擎 | 单元测试 |
| 所有搜索入口 | 默认路径一致，无遗漏 | 入口级测试或本地调用核验 |
| 两边均无结果 | 空结果报告完整、顺序准确、建议不重复 | 单元测试 |
| 匿名公开搜索 | 现有配额与限流不变，云端成本说明清晰 | 接口回归 + 文档检查 |
| 凭证安全 | 日志、诊断和页面不回显完整凭证 | 日志与响应检查 |
