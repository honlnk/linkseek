## 二、阶段一：商业兜底核心链路（Devin 引擎跑通）

对应设计方案：4.1（types/devin/manager）、4.2（fallback 注入）、4.3（凭证管理后端部分）、4.6 的**后端端点**（不含前端页）。

### 1.1 新增 `src/search/commercial/types.ts`（约 15 行）

- `CommercialEngine` 接口：`{ readonly id: string; available(): Promise<boolean>; search(query, maxResults): Promise<SearchResult[]> }`，输出复用现有 `SearchResult`。

### 1.2 新增 `src/search/commercial/devin.ts`（约 150 行）

移植 dsh-devin-search 的四块（设计方案第三节已列移植清单）：

- 粘贴码 OAuth：PKCE 生成（`randomBytes(64)` verifier + sha256 challenge）、授权 URL 构造（`https://app.devin.ai/auth/cli/continue`）、授权码交换（POST `https://api.devin.ai/auth/cli/token`）。
- **verifier 暂存方案（设计方案未细化，此处拍定）**：verifier 与 state 写入 SystemSetting 临时 key（`devinOAuthPending`，JSON，含签发时间戳），10 分钟过期；exchange 成功或过期即清除。与全局凭证同级存储，复用现有设施，无需进程内存态（无状态多实例友好）。
- 搜索客户端：双 host 故障转移（`server.codeium.com` → `server.self-serve.windsurf.com`），token 以 `devin-session-token$<jwt>` 形式注入；防御性字段解析（url/sourceUrl/webUrl/link 多键兜底）；URL 白名单校验。
- token 工具：`toDevinSessionToken()`、`expiry()`（JWT exp 解析，兜底 365 天）、`redact()`（日志脱敏）。
- 熔断：仅当**全部** host 返回 401/403 才判 token 失效，本地标记；单 host 故障不误杀。

### 1.3 新增 `src/search/commercial/manager.ts`（约 60 行）

- 读 `commercialEngines` 列表（JSON 数组，顺序即优先级），空/未设置 = 整体关闭返回空。
- 按序尝试：`enabled:false` 跳过；凭证缺失/失效跳过并记诊断；单引擎异常静默继续下一个。
- 熔断状态记录（某引擎鉴权连续失败 → 标记失效，后台可见）。

### 1.4 改 `src/search/fallback.ts`（约 +40 行）

- 顶部按 `provider` 参数分流：`auto` 走现有降级链；`cloud` 跳过降级链直接调 manager。
- 降级链全空后、返回空结果**之前**，调 manager 按列表兜底；命中则结果标注来源引擎。
- **诊断记录改动（注意，波及 3 个文件）**：兜底尝试记入 `diagnostics.attempts`，label 形如 `商业兜底:devin`。
  - `src/search/provider.ts:33` `SearchAttempt` 接口需加可选字段 `kind?: 'searxng' | 'commercial'`（区分两类尝试；**在字段注释里写明约定**：commercial 类尝试的 `language`/`engines`/`categories` 字段不适用、置 undefined，因为这些是 SearXNG 参数语义）。
  - `src/search/empty-hint.ts:16` 的渲染「已自动尝试 N 组参数」需把 commercial 尝试从「组参数」计数中排除或单独措辞（如「降级链 3 组参数均空，商业兜底 devin 亦无结果」），避免文案误导。
  - 这是设计方案未提到的波及面，施工时按此执行并记入施工日志。

### 1.5 引入 vitest 与测试

- `package.json` 加 devDependency `vitest`，加脚本 `"test": "vitest run"`。只装这一个，不引测试全家桶。
- 测试范围（全部用注入假 fetcher / 假凭证，不打真实外网）：
  - `devin.test.ts`：双 host 故障转移（首 host 500 → 次 host 命中）；熔断判定（双 host 均 401 → 标失效；单 host 401 → 不熔断）；`redact()` 脱敏；`expiry()` 从 JWT exp 解析与兜底。
  - `manager.test.ts`：列表为空返回空；`enabled:false` 跳过；前引擎失败静默续试后引擎；顺序严格按数组。
  - `fallback.test.ts`：`provider=auto` 且降级链有结果时**不**触发兜底；降级链全空且列表有引擎时触发兜底；`provider=cloud` 跳过降级链直打商业引擎。

### 1.6 阶段门禁（全绿才开阶段二）

1. `pnpm test` 全绿
2. `pnpm typecheck` 干净
3. 手动验收：本地起服务，后台 PUT 引擎列表写入假 Devin token → 调 `web_search` 搜一个冷门词使 SearXNG 全空 → 观察日志确认兜底链路被触发（mock/真打均可）。**无真实 Devin 账号时**：注入假 token + mock 双 host 响应验证链路连通，真实 OAuth 换 token 留阶段二前端就绪后由用户真人复核。
4. 本文档状态流转 + 施工日志追加。
