## 二、SearXNG —— 能配置什么 vs 我们配置了什么

> 这是搜索优化的核心。SearXNG 有大量未使用的配置能力。

### 2.1 SearXNG 的完整可配置项（分块）

#### `use_default_settings`（顶层，合并语义）

| 形式 | 行为 |
|---|---|
| `use_default_settings: true` | 继承官方默认全部配置（约 200 个引擎），你的覆盖项**按 key 合并** |
| `use_default_settings:` + `engines.keep_only: [...]` | 只保留指定引擎 |
| `use_default_settings:` + `engines.remove: [...]` | 移除指定引擎 |

**关键认知**：当 `use_default_settings: true` 时，再写 `engines:` 块是**按 name 合并**，**不会丢失**其他引擎。这是项目当前最大的认知盲区——以为不动 `engines` 是安全的，其实白白放弃了精确调控能力。

#### `search:` 块

| 配置项 | 作用 | 我们配的值 | 默认值 | 可选值 |
|---|---|---|---|---|
| `default_lang` | 默认搜索语言 | `"zh-CN"` | `"auto"` | locale 码 / `all` / `""`(auto) |
| `safe_search` | 安全过滤 | `0` | `0` | `0/1/2` |
| `formats` | 输出格式 | `[html, json]` | `[html]` | `html/csv/json/rss` |
| `autocomplete` | 自动补全后端 | `""`（关） | `""` | google/bing/ddg/… |
| `max_page` | 翻页深度上限 | 未配 | `0`(无限) | int |
| `ban_time_on_fail` | 引擎故障临时禁用秒数 | 未配 | `5` | int |
| `max_ban_time_on_fail` | 禁用上限 | 未配 | `120` | int |
| `suspended_times` | 按错误类型的挂起时长 | 未配 | 见下 | map |

`suspended_times` 默认值（影响故障引擎恢复速度）：
```yaml
SearxEngineAccessDenied: 180      # 402/403
SearxEngineCaptcha: 3600          # 验证码
SearxEngineTooManyRequests: 180   # 429
cf_SearxEngineCaptcha: 1296000    # Cloudflare 验证码（15天）
cf_SearxEngineAccessDenied: 86400 # Cloudflare 拦截（1天）
```

#### `server:` 块

| 配置项 | 作用 | 我们配的值 | 默认值 |
|---|---|---|---|
| `secret_key` | 加密用密钥 | 配了（dev 占位） | `ultrasecretkey` |
| `bind_address` | 监听地址 | `0.0.0.0` | `127.0.0.1` |
| `port` | 端口 | `8080` | `8888` |
| `limiter` | 限流/反爬 | `false` | `false` |
| `image_proxy` | 图片代理 | `false` | `false` |
| `method` | 搜索请求方法 | 未配 | `POST` |
| `public_instance` | 公开实例特性 | 未配 | `false` |

#### `outgoing:` 块（出站请求，**直接影响搜索质量**）

| 配置项 | 作用 | 我们配的值 | 默认值 |
|---|---|---|---|
| `proxies` | 出站代理 | `all://: __SEARXNG_PROXY__`（占位符，由 `docker-entrypoint.sh` 在启动时从 `SEARXNG_PROXY` 环境变量注入） | 无 |
| `request_timeout` | 单引擎超时 | **未配** | `3.0` 秒 |
| `max_request_timeout` | 超时上限 | **未配** | `10.0` 秒 |
| `useragent_suffix` | UA 后缀（**只能追加，不能替换**） | **未配** | `""` |
| `enable_http2` | HTTP/2 | **未配** | `true` |
| `retries` | 失败重试次数 | **未配** | 无 |
| `source_ips` | 绑定源 IP | **未配** | 无 |
| `networks` | 命名网络配置 | **未配** | 无 |

> ⚠️ **重要限制**：SearXNG **没有全局替换 User-Agent 的配置**，只有 `useragent_suffix` 追加后缀。要改 UA 得改引擎代码。

#### `engines:` 块（**最关键，当前完全空白**）

单个引擎可配置的项：

| 配置项 | 作用 | 默认值 |
|---|---|---|
| `name` | 引擎名（合并键） | 必填 |
| `engine` | Python 模块 | 必填 |
| `shortcut` | `!bang` 关键字 | - |
| `categories` | 所属分类 | - |
| `disabled` | 关闭但可被用户重新启用 | `false` |
| `inactive` | 完全移除 | `false` |
| **`weight`** | **权重，直接乘进 score** | **`1`** |
| `language` | 覆盖引擎语言 | - |
| `timeout` | 单引擎超时覆盖 | 全局值 |
| `send_accept_language_header` | 发送 Accept-Language | `false` |
| `display_error_messages` | 显示引擎错误 | `true` |
| `retry_on_http_error` | 特定错误码重试 | - |
| `network` | 引用的网络配置 | - |
| `proxies` | 单引擎代理覆盖 | 全局值 |

**完整分类（categories）列表**：`general` / `images` / `videos` / `news` / `map` / `music` / `it` / `science` / `files` / `social media`

#### `/search` API 查询参数（**JSON API**）

| 参数 | 作用 | 项目是否使用 | 备注 |
|---|---|---|---|
| `q` | 关键词 | ✅ 使用 | |
| `format` | 输出格式 | ✅ `json` | 必须在 `formats` 里启用 |
| `pageno` | 页码 | ✅ 使用 | |
| `language` | 语言 | ✅ 使用 | |
| `safesearch` | 安全过滤 | ✅ `0` | |
| `time_range` | 时间范围 | ✅ 使用 | |
| **`categories`** | **限定搜索分类** | ✅ 已使用（P0 暴露） | 可按 `it`/`science` 等过滤 |
| **`engines`** | **限定本次查询用哪些引擎** | ✅ 已使用（P0 暴露） | 逗号分隔引擎名/shortcut |
| `timeout_limit` | 单次查询超时覆盖 | ❌ 未使用 | |

> 🔴 **重大发现**：`engines=` 和 `categories=` 这两个参数官方 API 文档没写，但源码（`webadapter.py::parse_generic`）**确实支持**。项目完全可以按 query 语言动态选择引擎（英文 query → 只用 google/bing/ddg），却完全没用。

#### 响应字段

| 字段 | 项目声明 | 项目是否使用 |
|---|---|---|
| `results` | ✅ | ✅ 读取 |
| `unresponsive_engines` | ✅ 声明了 | ✅ 读取（P0 起记录 `logger.warn`） |
| `score`（每条结果） | ✅ 声明了 | ✅ 用于排序（P0 起按 score 降序） |
| `number_of_results` | ❌ | ❌ |

### 2.2 我们实际配置了什么

`searxng/settings.yml` 全部内容（**仅 39 行**）：

```yaml
use_default_settings: true          # ← 继承全部默认，零引擎定制

general:
  instance_name: "linkseek Search"
  debug: false

search:
  safe_search: 0
  autocomplete: ""
  default_lang: "auto"              # ← 按查询自动判断语言（P0 改进，原为 zh-CN）
  formats: [html, json]

server:
  secret_key: "dev-secret-..."
  bind_address: "0.0.0.0"
  port: 8080
  limiter: false
  image_proxy: false

ui:
  static_use_hash: true

outgoing:
  # 代理地址由 docker-entrypoint.sh 在容器启动时从 SEARXNG_PROXY 环境变量注入
  proxies:
    all://: __SEARXNG_PROXY__       # ← 占位符（本地 7897 / 生产 7890）
```

**P0 已实现的改进**：
- ✅ `default_lang` 改为 `auto`，英文 query 不再被强制带偏到中文结果
- ✅ API 的 `categories` / `engines` 参数已暴露给 MCP 工具
- ✅ 代码读取 `unresponsive_engines` 并记 `logger.warn`
- ✅ 结果按 `score` 降序排序
- ✅ URL 规范化去重（剥离 utm_* / fbclid 等追踪参数）

**仍未配置的重要项**（SearXNG 支持但未用）：
- ❌ `engines:` 块 —— 完全空白，不调权重、不启停引擎（路线 B，后续考虑）
- ❌ `outgoing.request_timeout` / `max_request_timeout` —— 用默认 3s/10s，慢引擎可能拖慢
- ❌ `outgoing.retries` —— 失败不重试

## 三、Browserless v2 —— 能配置什么 vs 我们配置了什么

> 关系到 `web_fetch_render` 的质量和 WAF 绕过能力。

### 3.1 Browserless v2 环境变量全集（开源版）

> ⚠️ v2 重写后**废弃了整个 `DEFAULT_*` 家族**（`DEFAULT_STEALTH`、`DEFAULT_LAUNCH_ARGS` 等全部失效）。网上多数教程是 v1 的，已过时。

#### 连接与限制

| 变量 | 默认值 | 作用 | 我们配的值 |
|---|---|---|---|
| `TOKEN` | **未设则随机生成** | 鉴权 token，WS 连接必带 | **`""`（空！）** ⚠️ |
| `CONCURRENT` | `10` | 最大并发会话 | `2` |
| `QUEUED` | `10` | 排队上限（超限返 429） | 未配 |
| `TIMEOUT` | `30000` ms | 单会话最大时长 | `200000` |
| `PORT` | `3000` | 监听端口 | 未配（用默认） |
| `HOST` | `localhost` | 绑定地址 | 未配 |
| `RETRIES` | `5` | 崩溃重试次数 | 未配 |

> 🔴 **重大发现**：我们 `TOKEN=` 设为空。Browserless v2 **强制要求鉴权**——空值会触发它启动时随机生成一个 token，并打到日志里。但我们的 `BROWSER_FETCH_URL` 默认值 `ws://localhost:9100/chromium/playwright` **没带 `?token=`**。这意味着要么连接被拒，要么依赖"开源版内网不强制"的旧行为。**这是一个潜在 bug。**

#### 文件系统与数据

| 变量 | 默认值 | 作用 |
|---|---|---|
| `DATA_DIR` | `$TMPDIR/browserless-data-dirs` | 每会话 user-data 目录（cookie/cache） |
| `DOWNLOAD_DIR` | `$TMPDIR/...` | 下载目录 |
| `SCRATCH_DIR` | `$TMPDIR/...` | Chromium TMPDIR |

#### 安全与请求

| 变量 | 默认值 | 作用 |
|---|---|---|
| `ALLOW_FILE_PROTOCOL` | `false` | 允许 `file://` |
| `ALLOW_GET` | `false` | 允许 GET 带 body |
| `CORS` | `false` | 启用 CORS |
| `MAX_PAYLOAD_SIZE` | `10MB` | 请求体上限 |

#### 健康与资源

| 变量 | 默认值 | 作用 |
|---|---|---|
| `HEALTH` | `false` | 启用请求前健康检查 |
| `MAX_MEMORY_PERCENT` | `99` | 内存超限拒绝请求 |
| `MAX_CPU_PERCENT` | `99` | CPU 超限拒绝请求 |

#### 代理（重要区分）

| 变量 | 作用 | 我们配的值 |
|---|---|---|
| `HTTP_PROXY` / `HTTPS_PROXY` | **只代理 browserless 进程自身的 HTTP 调用**（webhook 等），**不代理 Chromium 页面请求** | 配了（但对浏览器抓取无效！） |
| `EXTERNAL` | 对外广告 URL（旧名 `PROXY_URL`，易混淆） | 未配 |

> 🔴 **重大发现**：我们给 Browserless 配了 `HTTP_PROXY`，但这**不会代理 Chromium 的页面请求**。要让浏览器走代理，必须通过 launch args 传 `--proxy-server`。当前配置下，`web_fetch_render` 抓境外站点可能直连失败（取决于网络环境）。

#### WS 端点 `/chromium/playwright` 的查询参数（**全部未使用**）

| 参数 | 作用 | 默认值 |
|---|---|---|
| `token` | 鉴权 | 必填 |
| **`stealth`** | **启用 puppeteer-extra-stealth 插件**（反检测） | `false` |
| `blockAds` | 加载 uBlock Origin Lite | `false` |
| `headless` | 无头模式 | `true` |
| `acceptInsecureCerts` | 接受坏证书 | `false` |
| `slowMo` | 慢放每个动作 | `0` |
| **`launch`** | **base64 JSON，传 Chromium args**（如 `--proxy-server`、`--lang`、`--disable-blink-features=AutomationControlled`） | `{}` |

> 🔴 项目代码 `browserFetchProvider` 裸调 `chromium.connect({ wsEndpoint })`，**这些参数一个都没传**。没有 `stealth`、没有 `token`、没有 `launch` args。这是 `web_fetch_render` 对 WAF 站点也失效的根因。

### 3.2 开源版 vs 企业版的关键差异（反爬相关）

| 能力 | 开源版 | 企业版 |
|---|---|---|
| 基础 stealth（puppeteer-extra-stealth 插件） | ✅ `?stealth=true` | ✅ + 增强 |
| 指纹随机化 / BrowserQL / CAPTCHA 解决 / 住宅代理 | ❌ | ✅ |

**结论**：开源版的 `?stealth=true` 对付基础 WAF（如雪球）够用，但需要我们主动在 WS URL 里开启。

### 3.3 资源建议（当前配置偏紧）

| 项 | 当前值 | 建议 | 原因 |
|---|---|---|---|
| `shm_size` | **未配（默认 64MB）** | `2g` | Chromium 在 64MB 共享内存下易 OOM 崩溃，这是头号崩溃原因 |
| `mem_limit` | `1g` | `2g`（CONCURRENT=2 时） | 每会话约 300-500MB，两个重页可能撑爆 1g |

## 四、其余开源组件 —— 能配置什么 vs 我们配置了什么

### 4.1 Playwright（客户端侧）

项目用 `playwright-core` 的 `chromium.connect({ wsEndpoint })` 连接 Browserless。

**可配置但未使用的**：

| 能力 | 当前 | 可做 |
|---|---|---|
| `newContext({ userAgent })` | 默认 UA（headless 特征明显） | 伪装真实浏览器 UA |
| `newContext({ locale })` | 默认 | 设 `en-US` / `zh-CN` |
| `newContext({ extraHTTPHeaders })` | 无 | 补 `Accept-Language` 等 |
| `newContext({ viewport })` | 默认 | 设 1920×1080 |
| `page.goto({ waitUntil })` | `domcontentloaded`（太早） | WAF 场景用 `networkidle` 等挑战完成 |
| stealth 插件 | 无 | 通过 WS `?stealth=true` 启用 |

### 4.2 undici（HTTP 抓取侧）

项目通过 `undici` 的 `fetch` + 自定义 `dispatcher` 抓取网页。

**已配置**：

| 项 | 值 | 位置 |
|---|---|---|
| 请求头 | UA=`linkseek/0.1`、Accept、Accept-Language | `http-fetch.ts:11-15` |
| 超时 | `FETCH_TIMEOUT`（30s） | config |
| 重定向 | 手动逐跳，最多 `MAX_REDIRECTS`（5） | `http-fetch.ts:38-80` |
| 响应体上限 | `MAX_RESPONSE_SIZE`（5MB） | config |
| 内容截断 | 100KB | `http-fetch.ts:9` |
| SSRF Agent | `ssrfAgent`（带 safeLookup DNS 过滤） | `dispatcher.ts:25-27` |
| 内网 Agent | `internalAgent`（SearXNG 用，无 SSRF） | `dispatcher.ts:33` |
| 代理 Agent | `EnvHttpProxyAgent`（配了代理时） | `dispatcher.ts:42-48` |

**未配置但 undici 支持的**：

| 能力 | 说明 |
|---|---|
| Cookie jar | undici 不内置，需手动管理；当前无 cookie 持久化，WAF 挑战过不了 |
| HTTP/2 | undici 支持，未显式启用 |
| 连接池调优 | `Agent` 的 `connections`/`pipelining` 未调 |

### 4.3 Prisma

**已配置**：schema（3 个 model）、连接（`DATABASE_URL`）、日志级别、`globalThis` 单例缓存。

**可配置但未动的**：连接池大小（Prisma 默认值）、查询超时、重连策略。对当前规模够用，非搜索优化重点。

### 4.4 MCP SDK

**已配置**：无状态模式（每请求独立 transport+server）、Bearer Token 鉴权、4 个工具注册。

**可配置但未用的**：会话模式（SSE）、资源/提示词能力、日志通知。当前无状态模式适合 Nginx 反代，无需改。

### 4.5 Express / Session

**已配置**：`trust proxy`（生产）、JSON body、session（memorystore、8h 过期、httpOnly+samesite+lax）、`COOKIE_SECURE`。

**可配置但未用的**： Helmet 安全头（当前靠 Nginx 加）、请求体大小限制（用默认）。

## 七、针对「优化配置」的优先级建议

> 仅针对配置层面（不含后处理/重排/AI 汇总，那是下一步）。

### P0 —— 直接影响搜索质量与可用性

1. **配置 SearXNG `engines:` 块**
   - 为 Google / Bing / DuckDuckGo / Wikipedia 设 `weight`（如 google: 1.5, wikipedia: 2.0）
   - 评估禁用/降权明显带偏结果的引擎
   - 利用 `keep_only` 或 `disabled` 精简引擎集

2. **启用 API 的 `categories` / `engines` 参数**
   - `searxng.ts` 的搜索调用增加按 query 特征选引擎的逻辑（英文 query → google/bing/ddg）
   - 暴露 `categories` 为 `web_search` 工具的可选参数

3. **修复 Browserless `TOKEN` 配置**
   - 显式设 `TOKEN` 并在 `BROWSER_FETCH_URL` 拼 `?token=`

4. **补 `shm_size`**（防 Chromium 崩溃）

### P1 —— 提升 WAF 绕过与渲染质量

5. **`web_fetch_render` 启用 `?stealth=true`**
6. **传 launch args**：`--proxy-server`（让浏览器也走代理）、`--lang`、`--disable-blink-features=AutomationControlled`
7. **浏览器 context 伪装**：真实 UA、locale、viewport
8. **改抓取 UA**：`http-fetch.ts` 的 `linkseek/0.1` 换成真实浏览器 UA（或可配置）

### P2 —— 可观测性与调优

9. **读取 `unresponsive_engines`** 并写入日志/告警
10. **用 `score` 字段排序**结果
11. **配置 `outgoing.retries` / `request_timeout`**
12. **`HEALTH=true` + 资源阈值**（Browserless 自保）
