# linkseek MCP vs 内置工具（WebSearch / WebFetch）对比分析

> 基于 2026-08 实测：8 个搜索关键词、5 个抓取 URL、3 轮重复验证，共 30+ 次工具调用。
> 目的：定位 linkseek 相对内置工具的真实优劣势，为后续功能优化提供依据。

---

## 一、对比对象

| 维度 | 内置工具 | linkseek MCP |
|------|---------|--------------|
| 搜索 | `WebSearch` | `web_search` / `web_search_and_fetch` |
| 抓取 | `WebFetch`（带 prompt，取完用小模型回答） | `web_fetch` / `web_fetch_render` |
| 底层 | ZCode 平台内置（黑盒） | 自托管 SearXNG + Node 抓取 + Playwright 渲染 |
| 鉴权 | 无 | API Key（Bearer Token） |
| 部署 | 平台托管 | 自托管（Docker + 双层网关） |

## 二、搜索能力对比（三轮实测）

### 结果矩阵

| 关键词 | WebSearch | linkseek `web_search` | linkseek `search_and_fetch` |
|---|---|---|---|
| 智谱 GLM-5（中文） | ✅ 最全，自动多源汇总 | ✅ 5 条，质量好 | ⚠️ 雪球站正文 WAF 乱码 |
| Claude Code（英文） | ✅ 精准命中官方/GitHub | ⚠️ 跑偏到中文博客 | ⚠️ 同上 |
| xAI Grok 4 发布（中文） | ✅ 最全，带汇总表 | ✅ 5 条 | ⚠️ 雪球站又撞 WAF |
| OpenAI GPT-5 features（英文） | ✅ 精准官方+Wikipedia | ⚠️ 跑偏到 302.AI 测评 | ⚠️ 正文 OK 但偏题 |
| Next.js 15 App Router（中英） | ✅ 官方+教程 | ✅ 含官方 | ✅ 正常 |
| Tailwind v4 新特性（中文） | ✅ 10 条+汇总表 | ⚠️ 中文博客为主 | ⚠️ 镜像站正文 |
| Bun runtime（英文） | ✅ 精准官方+GitHub | ✅ 含官方+GitHub | ✅ 正文完整 |
| Next.js server components（英文） | ✅ 官方+深度文章 | ✅ 含官方 | ✅ 正常 |

### 稳定结论

- **WebSearch 中英文都更准**：直接命中官方源、Wikipedia、GitHub；且**自带结果汇总**（会自动整理成要点+链接表）。
- **linkseek `web_search` 对英文词容易跑偏**到中文转载站/测评站，命中官方源的比例低。
- **linkseek `search_and_fetch` 反复在带 WAF 的站点（雪球等）失败**，返回乱码——这是"自动批量取正文"模式的固有风险。

## 三、抓取能力对比（三轮实测）

### 结果矩阵

| URL | WebFetch | linkseek `web_fetch` | `web_fetch_render` | `webReader`(MCP) |
|---|---|---|---|---|
| docs.anthropic.com（301 重定向） | ❌ 跨域重定向直接停，需手动换 URL | ✅ 自动跟随 | ✅ 自动跟随 | ✅ 自动跟随 |
| react.dev（前端技术站） | ❌ **直接 404** | ✅ | ✅ | ✅ |
| nextjs.org/docs | ✅（中文概括） | ✅（英文正文） | ✅ | ✅ |
| tailwindcss.com/blog | ✅（中文概括） | ✅（完整） | ✅ | ✅ |
| nodejs.org / bun.sh/docs | ✅ | ✅ | ✅ | ✅ |

### 稳定结论

- **WebFetch 对技术站兼容性差**：react.dev 直接 404，docs.anthropic.com 卡 301——这是内置工具的**硬伤**。
- **linkseek 三个抓取工具 5/5 全成功**，且自动跟随重定向，稳定性完胜。
- **WebFetch 唯一优势**：带 prompt，取完用小模型回答问题，不只是返回原文。

## 四、linkseek 的优势（保持并强化）

### 1. 抓取稳定性（核心优势）
- 自动跟随 301/302 重定向，内置 WebFetch 会卡住。
- 对前端技术站（React/Next.js/Tailwind 官网）兼容性好，内置 WebFetch 频繁 404。
- **这是用户选择 linkseek 的第一理由**，已在三轮测试中 100% 复现。

### 2. JS 动态渲染（独有能力）
- `web_fetch_render` 用 Playwright + Chromium 渲染 SPA，内置工具**完全没有**这个能力。
- 对现代前端框架渲染的文档站、Dashboard、单页应用是刚需。

### 3. 一步搜+取
- `web_search_and_fetch` 一次调用完成"搜索 + 批量取正文"，省 token、省轮次。
- 内置工具需要先 `WebSearch` 再逐个 `WebFetch`，至少 2~N 次调用。

### 4. 自托管 + 可控
- 数据不经过第三方平台，API Key 自己管，用量可统计。
- SearXNG 引擎、抓取策略都可自定义，不受平台黑盒限制。

## 五、linkseek 的短板（重点优化方向）

### 短板 1：搜索质量不如内置工具 ⚠️ 高优先级

**现象**：
- 英文关键词容易跑偏到中文转载站/测评站，命中官方源（GitHub / 官方文档 / Wikipedia）的比例明显低于 WebSearch。
- 中文关键词基本可用，但深度和广度不如内置（内置会自动多源汇总）。

**根因分析**：
- SearXNG 默认引擎配置可能偏向中文结果，或对英文官方源的权重不足。
- 缺少结果**重排序 / 去重 / 汇总**后处理——内置 WebSearch 会自动把多源结果整理成要点摘要，体验上"更聪明"。

### 短板 2：`search_and_fetch` 在反爬站点返回乱码 ⚠️ 高优先级

**现象**：
- 雪球（xueqiu.com）等带 WAF 的站点，`search_and_fetch` 取到的正文是一长串 `_waf_xxx` 乱码，三轮测试**100% 复现**。
- 乱码会污染整个返回结果，用户看到后体验很差。

**根因分析**：
- 抓取时缺少浏览器指纹（UA / Cookie / JS 执行），被 WAF 识别为爬虫。
- 没有失败检测：取到乱码也不会跳过，直接塞进结果。

### 短板 3：搜索结果缺少"智能汇总" ⚠️ 中优先级

**现象**：
- 内置 WebSearch 会把多条结果整理成结构化摘要（要点 + 对比表 + 链接清单），linkseek 只返回原始列表。
- 对 AI 调用方来说，原始列表需要二次处理，而内置的汇总"开箱即用"。

### 短板 4：缺少"取完即答"能力 📌 低优先级

**现象**：
- WebFetch 支持 `prompt` 参数，取完正文直接用小模型回答问题。
- linkseek 的 `web_fetch` 只返回原始 Markdown，AI 还要自己读再总结。

## 六、优化建议（按优先级排序）

### P0 - 搜索质量提升
1. **SearXNG 引擎调优**
   - 调整 engines 配置，提高 GitHub / 官方文档域名 / Wikipedia 的权重。
   - 英文 query 强制走 Google / Bing / DuckDuckGo 英文源，避免被中文引擎带偏。
   - 增加 `language` 参数的真正生效（目前疑似不影响实际引擎选择）。

2. **结果后处理**
   - 去重（同一 URL 不同镜像站）。
   - 按"官方源 > 权威媒体 > 博客 > 转载站"重排序。
   - 可选：对前 N 条结果做摘要（轻量 LLM 调用或规则提取）。

### P0 - `search_and_fetch` 反爬兜底
1. **正文质量检测**：抓取后检测是否为乱码 / WAF 挑战页（特征：`_waf_`、超长 base64、无正常中文/英文段落），命中则**自动降级到 `web_fetch_render`**（Playwright 渲染能绕过大部分 WAF）。
2. **失败跳过**：单条正文抓取失败不应污染整体结果，降级为"仅返回摘要 + URL"。
3. **请求头增强**：补充真实浏览器 UA、Accept-Language、Referer，降低被识别概率。

### P1 - 搜索结果汇总
- 参考 WebSearch 的体验，在 `web_search` 增加可选的 `summarize: true` 参数，对 top 结果做要点提取。
- 或新增独立工具 `web_search_summary`，避免改变现有工具语义。

### P2 - `web_fetch` 支持 prompt
- 增加可选 `prompt` 参数，取完正文后调用小模型回答，对标 WebFetch 体验。
- 需评估是否引入 LLM 依赖（成本 / 延迟 / 隐私）。

### P2 - 抓取兼容性持续补强
- 建立"难抓站点"测试集（React 官网、Anthropic 文档、SPA 文档站等），纳入回归。
- 对 403 / 404 / 重定向循环做更友好的错误提示。

## 七、推荐搭配（给用户的最终建议）

| 场景 | 推荐工具 | 理由 |
|---|---|---|
| 搜索（中英文） | 内置 `WebSearch` | 三轮都更准、更全，自带汇总 |
| 已知 URL 取正文 | linkseek `web_fetch` | 全胜，自动跟重定向 |
| URL 取正文 + 问答 | 内置 `WebFetch`（URL 稳定时） | 带小模型，但技术站易 404 |
| JS 动态 / SPA 页面 | linkseek `web_fetch_render` | 唯一能渲染 |
| 搜了就要正文 | linkseek `web_search_and_fetch` | 省调用（WAF 站除外） |

**一句话**：搜索用内置，抓取用 linkseek。等 P0 优化落地后，搜索也可切到 linkseek，实现全链路自托管。
